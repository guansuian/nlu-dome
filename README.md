# 蚊虫监测 NLU

使用 MacBERT 编码一次，预测查询任务的意图及各任务对应的实体。支持一个问题中出现多种意图，以及同一种意图对应多个任务。代码注释按中文步骤组织。

当前已实现数据读取、训练、验证、保存、重新加载和预测。后台接口调用、日期标准化、业务参数校验和追问流程尚未实现，需要先确定后台接口和各意图的字段规范。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `config.py` | 默认路径及设备选择 |
| `dataset.py` | 读取标注、检查实体位置、转换 token 标签 |
| `model.py` | 共享编码器、任务意图和实体预测层、模型保存加载 |
| `train.py` | 组织训练、验证和选择检查点 |
| `predict.py` | 加载本地模型并预测 |

## 数据约定

训练文件放在 `data/train/`，验证文件放在 `data/validation/`，最终测试文件放在 `data/test/`。业务数据按意图组织到 `species_compose_report/` 和 `region_rank_report/` 子目录，读取器会递归读取指定目录及其子目录中的 `.jsonl` 文件；`unknown.jsonl` 和 `unknown_rank.jsonl` 放在 `data/train/` 根目录。读取器支持标准 JSONL，也支持当前为了阅读而展开、用空行隔开的 JSON 对象；后者不是严格的 JSONL。

每条样本使用 `text` 和 `tasks`。每个任务包含 `intent` 和 `entities`，实体包含 `type`、`text`、`start`、`end`。实体位置使用 Python 字符索引，包含起点、不包含终点。未知问题写为 `tasks: []`。一个已标注任务的 `entities: []` 表示确实没有实体，不表示尚未标注。

任务必须按查询在原文中出现的先后顺序标注。相同意图的多个查询也分别标注为任务；共享条件可在不同任务里重复引用。每个任务内目前使用 BIO 标签，不支持重叠实体。超过最大长度、任务数量上限或实体边界不能与分词对齐时会报错，避免静默丢失标注。

数据读取不根据文件名推断标签，所有标签以样本内容为准。`data/pending/` 不参与训练。当前训练集共 5392 条，业务意图包括 `species_compose_report` 和 `region_rank_report`，未知问题使用空任务列表。v8 仅学习了其中原有的 2192 条；v9 使用此前的 4192 条完成训练；v10 新增 1200 条任务边界与上下文数据，已用全部 5392 条完成训练。独立验证集 160 条，测试集 142 条（历史 78 条、新题 64 条）。

## 模型如何分组

MacBERT 输出的文本特征供后续处理复用。模型默认有 4 个任务位置，每个位置预测业务意图或 `__none__`。再将该位置的意图向量与文本特征结合，预测属于这个任务的 BIO 实体标签。

训练时实体分支使用标注意图；验证和预测使用模型自己预测的意图。未激活的位置不输出任务。实体提取不需要再次调用 MacBERT。无业务任务时返回澄清提示。

训练时根据训练集统计空位置和真实任务的数量，真实任务权重为 1；空位置权重为 `min(1, 真实任务数 / 空位置数)`。如果某类位置完全不存在，则使用权重 1，避免除零。权重在训练开始时计算并打印，保存到 `nlu_config.json` 的 `training.intent_loss_weights` 中。意图损失按位置加权后取平均，实体损失不变；不在预测时强行补出任务。已有模型需要重新训练才会应用这个调整，权重并不保证识别效果。

这是固定任务上限的基础方案，任务顺序是监督信号，预测错误的意图可能进一步影响实体。它需要多任务和同意图重复任务样本才能学习归属；添加预测层本身不保证识别效果。模型不会自动强制每种意图的字段白名单、必填项或取值规则。

```bash
python3 -m venv .venv

```

预训练模型默认是 `hfl/chinese-macbert-base`，缓存位于 `.cache/huggingface/`。已有缓存时，可通过 `HF_HUB_OFFLINE=1` 离线使用。

## 检查流程

```bash
HF_HUB_OFFLINE=1 .venv/bin/python train.py --smoke-test --device cpu
```

只用现有数据训练一个批次，然后保存并从磁盘重新加载进行预测。输出到 `models/joint_nlu_smoke/`，不使用训练集冒充验证集，不报告识别准确率。该检查点仅供流程检查。

## 正式训练

直接运行 `train.py` 即可完整训练 `data/train/` 及其子目录中的全部标注，包括当前单意图数据。默认使用 Apple GPU（MPS）：

```bash
HF_HUB_OFFLINE=1 .venv/bin/python train.py --device mps
```

默认使用 Apple GPU（MPS），不可用时明确报错；可显式选 `cpu`、`cuda` 或 `auto`。默认训练 10 轮、批次大小 2，MacBERT 学习率 2e-5、新预测层学习率 1e-3，最大长度 128、最多 4 个任务。新预测层可用 `--head-learning-rate` 单独调整；10 轮是训练上限，当前验证集用于从这 10 轮中选择最优检查点；不能仅增加轮数来保证效果。可用同名命令行参数修改，完整选项见 `train.py --help`。

提供验证集时，每轮在独立验证集上检查意图列表和完整任务的精确匹配率。完整任务匹配检查实体类型、位置和任务归属，忽略输出任务顺序；保留同意图任务的数量。按完整任务匹配率保存最优检查点，分数相同时保留较早的检查点。验证目录不存在或没有样本时，仍完整训练所有轮次，保存最后一轮，不计算或报告验证准确率。后续增加其他业务意图时，需要补充对应的单任务和混合任务标注。

保存后会打印训练集拟合检查，明确区分于独立验证准确率。没有学好训练集时，即使意图正确，也可能漏提实体或预测错误边界。

输出到 `models/joint_nlu/`，保存权重、分词器、标签映射、模型配置、训练参数、数据指纹和验证指标。输出目录非空时拒绝覆盖；再次训练请通过 `--output-dir` 指定新的目录。每次训练均从指定的预训练骨干开始，不自动续训。

## 预测

直接运行 `predict.py`（包括在 PyCharm 中运行）会进入交互输入模式。模型只加载一次，可连续输入问题；输入 `/exit`、按 Ctrl+C 或结束输入退出。空行跳过，输入过长会提示后继续。需要先在默认目录保存正式模型，或用 `--model-dir` 指定已有模型。

```bash
.venv/bin/python predict.py
```

指定 `--text` 仍支持单次预测：

```bash
.venv/bin/python predict.py --model-dir models/joint_nlu --text '深圳市最近7天雌性白纹伊蚊有多少只？'
```

预测前会检查输入编码，遇到无效 Unicode 字符会提示重新输入，交互进程不会因此退出；不会静默删除字符，以免改变实体位置。

预测返回 `text` 和 `tasks`，每个任务包含意图及实体原文位置。`__none__` 是空任务类别，不代表可靠的开放领域拒识；需要未知样本和真实问题评估。当前未对分数作置信度校准。
